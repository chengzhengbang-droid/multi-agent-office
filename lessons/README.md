# 成长记录

这里记的是**判断**，不是改动。改了什么 `git log` 里有，抄到这里没有任何价值。
这里只记：哪个假设错了、哪个坑是踩过才知道的、下次遇到同类问题该怎么想。

拆成一个目录而不是一个文件，是因为教训有维度：前端的坑对改事件投影的人没用，
反过来也一样。一个几千行的大文件的实际结局是没人读第二遍，于是它等于不存在。

## 先读这个

[**rules.md** — 沉淀下来的规矩](rules.md)。跨维度、被验证过不止一次的判断，必读，且必须保持短。
做任何非常规决定之前先过一遍这一节。

## 按维度分卷

| 文件 | 装什么 | 大致对应的代码 |
| --- | --- | --- |
| [rules.md](rules.md) | 沉淀下来的规矩（跨维度，出现两次以上才进来） | 全部 |
| [event-log.md](event-log.md) | 事件日志、投影、回放兼容性 | `src/core/event-store.ts`、`*-read-model.ts`、各 `apply*Event` |
| [collaboration.md](collaboration.md) | 多 Agent 协作、审核、闸门、什么时候叫人 | `src/core/collaboration*.ts`、`review-*.ts`、`reviewer-routing.ts`、`approval-index.ts` |
| [frontend.md](frontend.md) | 前端与渲染 | `src/web/**` |
| [backend.md](backend.md) | 服务端、Agent 运行时、桌面端 | `src/server.ts`、`src/runtime/**`、`src/desktop/**`、`src/electron-main.ts` |
| [process.md](process.md) | 工程流程：提交、回滚、测试、文档、约定本身 | 仓库约定、CI、`src/tools/**` |

**放哪个文件？** 按"下一个人会因为在改什么而需要这条"来放，不是按你这次动了哪些文件。
一条教训横跨两个维度时，写进最可能被读到的那一卷，另一卷只留一行指针，不要复制正文——
两份会各自演化，然后开始互相矛盾。

## 怎么写

**每次改完代码，在对应分卷的「变更日志」最上面加一条。** 但先过这一关：

> 下一个 Agent 如果不知道这条，会不会重犯同样的错？

会 → 写。不会 → 写一条**无教训**记录，说清这次改了什么、为什么不构成教训：

```markdown
### 2026-09-04 · 无教训 · 跟着已有的 provider 预设加了一条，没有新判断
```

不许留白，也不许凑数。留白的话，"这次真的没有"和"忘了写"从记录上看一模一样；
凑数的话，一个塞满流水账的文件等于没有文件。所以两条路都要付一句话的成本，
而这一句话是给下一个人看的——他要能据此判断该不该点开这条。

其余几条规矩：

- **一条记录 = 一个能迁移到下次的判断**，不是一个 changelog 条目。写"背景 / 教训 / 以后怎么做"，
  重点在后两项；背景一两句能让人看懂就够。
- **被审核者挑出来的问题，尤其值得记**。那是别人替你发现的盲区，是这里最贵的原料。
- **发现旧条目被推翻了，就地改掉并注明**，不要留两条互相矛盾的记录让后来者自己猜。
- **同一类教训出现两次以上，提炼进 [rules.md](rules.md)**，并在原处留下出处。
  变更日志会越来越长没人看完，规矩那一卷是真正被读的部分，所以它必须保持短。
- **新开一卷要慎重**。维度多到需要挑，就没人挑了。现有六卷装不下再开，并在这张表里登记。

## 格式

每卷分卷文件的骨架固定，`pnpm run check` 会校验：

```markdown
# 标题

**适用范围**：一句话说明这一卷装什么。

## 变更日志

新的写在最上面。

### YYYY-MM-DD · 标题
（可选中间段，比如 commit 短哈希：`### YYYY-MM-DD · 04fd933 · 标题`）
```

## 这件事有机制兜着

光靠约定不行——[规矩 7](rules.md#7-措辞改不动的事情用机制去改) 说的就是这个。
`pnpm run check` 里带一道 `lessons` 闸门：这次改动碰了代码，`lessons/` 的某个分卷
就必须多出一条新条目（教训或无教训都行，但都得写清楚）。CI 在 PR 上跑同一道闸门。

想看它具体怎么判：`src/tools/lessons-guard.ts`，测试在 `test/lessons-guard.test.ts`。
