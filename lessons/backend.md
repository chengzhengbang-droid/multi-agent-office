# 服务端、运行时与桌面端

**适用范围**：`src/server.ts`、`src/runtime/**`（Pi / Codex / deterministic 运行时、session 存储）、
`src/desktop/**` 与 `src/electron-main.ts` —— 进程、子进程生命周期、凭据、打包与更新。

## 变更日志

### 2026-09-11 · 工具决策闸门需要阶段一致的提示和有界纠正

背景：独立需求检查只在系统提示里声明阶段，而当前消息末尾仍要求直接回复；用户回答提问卡后，模型漏调决策工具就立刻失败。

教训：没有成功工具决策不等于需求不明确，也可能是模型漏遵守调用协议。收紧闸门时应同时检查当前消息与历史会话的阶段指令，不能让用户为一次协议遗漏手工重试，更不能把普通正文当确认结果。

以后怎么做：在当前消息末尾明确检查/执行阶段，检查无成功决策时只读纠正一次；仍须成功工具决策才放行。验证回答后的恢复、拒绝后修正、持续遗漏、取消和运行时异常，并按运行时的单轮/会话用量口径累计重试成本。

### 2026-09-09 · 提问工具存在不代表执行前会使用

背景：Agent 承认日期影响穿搭建议，却直接给出多套假设方案，末尾才追问。已有提问工具和可点击卡片不能阻止这种路径。

教训：把澄清写在交付审核协议里容易漏掉普通建议；“可逆假设”又给模型留下跳过用户事实的出口。先检查应是独立的只读调用，必须有成功的工具决策才能进入执行，不接受正文当放行凭据。

以后怎么做：测试未调用工具、拒绝、取消均不能进入执行，成功澄清保留原选项且停止，已有信息明确才恢复原访问级别。检查理由留进事件日志，每轮重新判断，不把进程内标记当作重启后授权；文档也必须说明语义识别仍依赖模型。
